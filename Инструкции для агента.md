# Инструкции для агента

## Роль

Ты реализуешь персональный Apple-native планировщик задач. Работай как senior SwiftUI/macOS engineer: сначала сохраняй простую локальную архитектуру, затем расширяй функциональность. Не превращай проект в web app и не переноси React-прототип напрямую.

## Главный источник контекста

Перед началом работы прочитай:

1. `Контекст для агента - Apple планировщик.md`
2. `Глобальный план проекта.md`
3. `Kimi_Agent_Apple Task Planner UI.zip`

Архив с React/Vite UI нужен как дизайн-референс:

- структура экранов;
- визуальная иерархия;
- macOS sidebar/main/detail layout;
- iOS companion screens;
- компоненты TaskRow, Kanban card, Calendar week view, Detail inspector.

Не используй React как целевой стек приложения.

## Целевой стек

- SwiftUI Multiplatform.
- SwiftData.
- macOS first.
- Shared Core + separate platform UI.
- JSON export/import.
- Xcode для создания проекта, сборки, подписи и запуска.
- Bundle Identifier: `com.pavel.planner`.

Будущие технологии:

- UserNotifications.
- Backend sync через собственный сервер.

Не начинай с будущих технологий, пока локальный macOS MVP не готов.
CloudKit/iCloud не использовать как целевой sync-механизм без отдельного явного решения пользователя: Personal Team не поддерживает iCloud capability.

## Доменная модель

### PlannerTask

Поля:

- `id`
- `title`
- `notes`
- `status`
- `priority`
- `scheduled`
- `due`
- `createdAt`
- `updatedAt`
- `completedAt`
- `project`
- `tags`
- `checklistItems`
- `manualOrder`

Минимально обязательные поля:

- `title`
- `status`
- `priority`
- `scheduled`
- `due`
- `createdAt`
- `updatedAt`
- `completedAt`
- `project`
- `notes`

### TaskStatus

Поддерживаемые значения:

- `inbox`
- `planned`
- `in-progress`
- `done`
- `cancelled`

Не добавляй `backlog` и `waiting` в MVP, если это не требуется явно.

### Priority

Поддерживаемые значения:

- `none`
- `low`
- `medium`
- `high`
- `urgent`

Сортировка:

```text
urgent > high > medium > low > none
```

### Project

Поля:

- `id`
- `title`
- `status`
- `deadline`
- `notes`
- `createdAt`
- `updatedAt`

Страница проекта должна показывать задачи этого проекта.

### ChecklistItem

Поля:

- `id`
- `title`
- `isDone`
- `order`

Не делать вложенные подзадачи в MVP.

## Правила списков

### Inbox

Фильтр:

```text
status == inbox
```

Сортировка:

```text
priority desc
createdAt asc
```

### Today

Фильтр:

```text
status != done
status != cancelled
and (
  scheduled <= today
  or due <= today
)
```

Просроченные задачи должны оставаться в Today, пока они не закрыты.

Сортировка:

```text
priority desc
due asc
scheduled asc
```

### Upcoming

Фильтр:

```text
status != done
status != cancelled
and (
  scheduled between today and today + 7 days
  or due between today and today + 7 days
)
```

Сортировка:

```text
scheduled asc
priority desc
```

Можно группировать как:

- Сегодня;
- Завтра;
- Эта неделя;
- Позже;
- Без даты.

### Completed

Фильтр:

```text
status == done
or status == cancelled
```

Сортировка:

```text
completedAt desc
updatedAt desc
```

### Projects

Показывать активные задачи проекта:

```text
status != done
status != cancelled
```

## Kanban

Колонки MVP:

- Inbox;
- Planned;
- In Progress;
- Done;
- Cancelled.

Требования:

- drag-and-drop между колонками;
- перенос карточки меняет `status`;
- ручной порядок сохраняется в `manualOrder`;
- карточка показывает title, priority, scheduled, due, project;
- пустые колонки можно скрывать настройкой.

## Calendar

Реализовать только week view:

- Monday first;
- 24-hour format;
- 30-minute slots;
- now indicator желательно, но не блокирует MVP;
- all-day row для задач без времени;
- показывать `scheduled`;
- показывать `due`;
- клик по задаче открывает detail inspector;
- drag в календаре меняет `scheduled`.

Не делать day/month view в MVP.

## JSON backup

JSON export/import обязателен в MVP.

Backup должен включать:

- tasks;
- projects;
- tags;
- settings;
- schemaVersion.

Правила:

- import не должен повреждать текущую базу при ошибке;
- неизвестная версия схемы должна обрабатываться явно;
- пользователь должен видеть понятную ошибку при невалидном JSON;
- JSON backup остается fallback даже после появления backend sync.

## UI-направление

Для macOS:

- sidebar слева;
- основной список/канбан/календарь по центру;
- detail inspector справа;
- плотный, спокойный, нативный интерфейс;
- без маркетинговых hero-секций;
- без декоративных карточек ради карточек;
- не вкладывать cards внутри cards;
- учитывать light/dark/system appearance;
- использовать SF Symbols, если доступны;
- не использовать lucide в SwiftUI-приложении.

Для iOS позже:

- TabView;
- NavigationStack;
- task detail bottom sheet;
- крупные touch targets;
- не дублировать бизнес-логику.

## Рабочий порядок для агента

1. Сначала прочитай контекст и план.
2. Проверь текущую структуру репозитория.
3. Если проекта Xcode еще нет, создай SwiftUI Multiplatform project.
4. Не вноси backend sync/UserNotifications/iOS scope в ранние задачи.
5. Делай маленькие проверяемые шаги.
6. После изменения модели данных проверяй сохранение после перезапуска.
7. После изменения фильтров проверяй Inbox/Today/Upcoming/Completed.
8. После UI-изменений проверяй light/dark и разные размеры окна.
9. Не удаляй пользовательские файлы и не перетирай дизайн-архив.
10. Перед завершением сообщай, что реализовано и что проверено.

## Короткий стартовый промпт

Сделай персональный Apple-native планировщик задач на SwiftUI Multiplatform + SwiftData. За основу бери только планировщик из моего Obsidian: задачи с `title/status/priority/scheduled/due/project/notes/checklist`, списки Inbox/Today/Upcoming/Completed, Kanban по статусам, недельный Calendar и Projects. Первый этап - локальный macOS MVP с JSON export/import. Не добавляй контакты, дни рождения, медиа, погоду, Pomodoro, time tracking, NLP, Google/Microsoft Calendar, backend sync, CloudKit, notifications и полноценный iOS UI до завершения macOS MVP. Для синхронизации после MVP использовать backend sync через собственный сервер, а не CloudKit/iCloud.
