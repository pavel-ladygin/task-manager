# Глобальный план проекта: Apple-планировщик задач

## Цель проекта

Сделать персональный Apple-native планировщик задач для личного использования в Apple-экосистеме.

Первый рабочий результат: стабильное локальное macOS-приложение на SwiftUI + SwiftData для базового планирования задач, проектов, списков, канбана и недельного календаря.

React/Vite-прототип из архива `Kimi_Agent_Apple Task Planner UI.zip` использовать как дизайн-референс и карту экранов, но основное приложение делать нативно на SwiftUI.

## Техническое направление

- SwiftUI Multiplatform.
- macOS first.
- SwiftData для локального хранения.
- JSON export/import для резервных копий и защиты от миграционных ошибок.
- Shared Core + отдельный platform UI для macOS и iOS.
- Backend sync через собственный сервер для синхронизации Mac и iPhone без Apple Developer Program.
- Xcode для создания проекта, сборки, подписи и запуска.
- Cursor/Codex для основной разработки.

Не начинать с backend sync, UserNotifications, iOS-подписи и внешних календарей. Эти части важны, но идут после стабильного локального MVP. CloudKit/iCloud не является целевым способом синхронизации для проекта, потому что требует платной Apple Developer Program.

## Этап 1. Основа проекта и доменная модель

Цель: создать технический фундамент, который не придется переделывать при добавлении iOS и синхронизации.

Работы:

- Создать SwiftUI Multiplatform App.
- Зафиксировать Bundle Identifier: `com.pavel.planner`.
- Настроить macOS как основной таргет разработки.
- Создать структуру проекта:
  - `Core/Models`;
  - `Core/Services`;
  - `Core/Utils`;
  - `Features`;
  - `macOS`;
  - `iOS`.
- Реализовать SwiftData-модели:
  - `PlannerTask`;
  - `Project`;
  - `Tag`;
  - `ChecklistItem`;
  - `AppSettings`.
- Реализовать enums:
  - `TaskStatus`;
  - `Priority`.
- Добавить базовые CRUD-операции для задач и проектов.

Критерии готовности:

- Приложение запускается на macOS.
- Можно создать задачу.
- Задача сохраняется после перезапуска.
- Можно создать проект.
- SwiftData-схема не зависит от UI.

## Этап 3. Списки задач, фильтры, сортировки и проекты

Цель: перенести основной workflow из текущего Obsidian-планировщика.

Работы:

- Inbox:
  - фильтр `status == inbox`;
  - сортировка `priority desc`, `createdAt asc`.
- Today:
  - активные задачи, у которых `scheduled` или `due` сегодня или раньше;
  - просроченные задачи остаются в Today до закрытия;
  - сортировка `priority desc`, `due asc`, `scheduled asc`.
- Upcoming:
  - активные задачи на ближайшие 7 дней;
  - секции: Сегодня, Завтра, Эта неделя, Позже, Без даты;
  - сортировка `scheduled asc`, `priority desc`.
- Completed:
  - `status == done` или `status == cancelled`;
  - сортировка `completedAt desc`, `updatedAt desc`.
- Projects:
  - список активных проектов;
  - страница проекта;
  - задачи проекта;
  - прогресс по задачам.
- Базовый поиск:
  - title;
  - notes;
  - project title.

Критерии готовности:

- Каждый список показывает ожидаемые задачи.
- Изменение статуса/дат сразу отражается во всех списках.
- Страница проекта показывает задачи выбранного проекта.
- Поиск не ломает фильтры разделов.

## Этап 4. Kanban

Цель: реализовать визуальное управление задачами по статусам.

Работы:

- Колонки:
  - Inbox;
  - Planned;
  - In Progress;
  - Done;
  - Cancelled.
- Карточка задачи показывает:
  - title;
  - priority;
  - scheduled;
  - due;
  - project.
- Drag-and-drop между колонками.
- При переносе карточки обновлять `status`.
- Сохранять ручной порядок карточек в `manualOrder`.
- Добавить настройку скрытия пустых колонок.

Критерии готовности:

- Карточку можно перенести между статусами.
- Новый статус сохраняется после перезапуска.
- Ручной порядок карточек сохраняется.
- Empty state не ломает layout.

## Этап 5. Недельный календарь

Цель: дать календарное представление без интеграции с внешними календарями.

Работы:

- Week view.
- Понедельник как первый день недели.
- 24-часовой формат.
- Шаг сетки 30 минут.
- All-day зона для задач без времени.
- Показывать `scheduled`.
- Показывать `due` как дедлайны.
- Задачи с временем отображать в сетке времени.
- Клик по задаче открывает detail inspector.
- Перенос задачи в календаре меняет `scheduled`.

Критерии готовности:

- Задачи корректно отображаются в нужные дни недели.
- Задачи без времени не теряются.
- Изменение даты в detail inspector отражается в календаре.
- Drag-and-drop в календаре обновляет дату/время задачи.

## Этап 6. JSON backup, импорт и устойчивость данных

Цель: защитить личные данные на раннем этапе разработки.

Работы:

- JSON export:
  - tasks;
  - projects;
  - tags;
  - settings;
  - schemaVersion.
- JSON import:
  - восстановление задач;
  - восстановление проектов;
  - восстановление чеклистов;
  - обработка неизвестной версии схемы.
- Валидация:
  - пустой `title` запрещен;
  - `updatedAt` обновляется при изменениях;
  - `completedAt` выставляется при `done`;
  - `completedAt` очищается при возврате из `done`, если это ожидаемое поведение.
- Опционально: одноразовый импорт задач из Obsidian markdown frontmatter.

Критерии готовности:

- Export создает валидный JSON.
- Import восстанавливает данные в чистой установке.
- Ошибка импорта не повреждает существующую базу.
- Есть понятное сообщение об ошибке при невалидном файле.

- Нет критичных layout-проблем на обычных размерах окна Mac.

## Этап 9. Уведомления

Цель: добавить напоминания после стабилизации модели задач.

Работы:

- Подключить UserNotifications.
- Запрашивать разрешение.
- Создавать уведомления для задач с датой/временем.
- Пересоздавать уведомления при изменении задачи.
- Отменять уведомления при выполнении, отмене или удалении задачи.
- Добавить настройку напоминания заранее.

Критерии готовности:

- Уведомление приходит в заданное время.
- Изменение даты не оставляет старое уведомление.
- Выполненная или удаленная задача не присылает уведомление.

## Этап 10. Backend sync

Цель: синхронизировать Mac и iPhone через собственный backend-сервер без зависимости от CloudKit/iCloud и платной Apple Developer Program.

Допущение: backend-сервер у пользователя уже есть. Перед реализацией нужно зафиксировать базовый URL, способ авторизации и формат sync API.

Работы:

- Спроектировать минимальный backend sync API для задач, проектов, тегов, чеклистов и настроек.
- Добавить client sync service в Core.
- Реализовать push локальных изменений на сервер.
- Реализовать pull изменений с сервера в локальную SwiftData-базу.
- Добавить `updatedAt`/UUID-based конфликт-резолв на первом этапе.
- Обеспечить offline-first поведение.
- Проверить конфликты и повторные изменения.
- Сохранить JSON backup как ручной fallback.

Критерии готовности:

- Задача, созданная на Mac, появляется на iPhone.
- Задача, измененная на iPhone, появляется на Mac.
- Приложение работает без интернета.
- Конфликтные изменения решаются предсказуемо.
- Синхронизация не требует iCloud capability и платной Apple Developer Program.

## Приемка MVP

MVP готов, если:

- приложение запускается на macOS;
- можно создать задачу;
- задача сохраняется после перезапуска;
- можно назначить статус, приоритет, проект, `scheduled` и `due`;
- Today показывает сегодняшние и просроченные активные задачи;
- Upcoming показывает задачи на ближайшие 7 дней;
- Completed показывает закрытые задачи;
- Kanban позволяет переносить задачу между статусами;
- Calendar показывает задачи на неделе;
- изменение даты в задаче отражается в календаре;
- страница проекта показывает задачи проекта;
- JSON export создает резервную копию;
- JSON import восстанавливает данные.
